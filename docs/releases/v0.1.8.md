## 음악 정보 채우기 v0.1.8

되돌리기용 백업을 더 안전하게 다루도록 고친 버전입니다. 검색·화면은 v0.1.7과 같습니다.

### 고친 것

- **파일 이름을 바꿀 때 백업을 놓치던 문제.** "저장할 때 파일 이름 바꾸기"를 켜고 저장할 때 백업(`.tagbak.json`)이 잠깐 열려 있으면(백신·검색 색인 등), 음악 파일만 `가수 - 제목.mp3`로 바뀌고 백업은 옛 이름에 남아 **되돌리기가 "백업 없음"** 이 될 수 있었습니다.
  - 이제 음악 파일과 백업은 항상 함께 바뀌거나 둘 다 그대로 있습니다. 이름을 바꾸지 못하면 태그는 저장하고 "이름을 바꾸지 못함(사용 중 — 태그는 저장했고 되돌릴 수 있음)"이라고 경고합니다. 전에는 이 경우를 저장 실패로 잘못 알렸습니다.
- **깨진 백업이 있으면 저장하지 않습니다.** 이미 있는 백업(처음 원래 정보)을 저장 전에 읽어 보고, 읽을 수 없으면 아무것도 쓰지 않고 알려 줍니다. 전에는 태그를 쓴 뒤에야 되돌리기가 안 된다는 것을 알 수 있었습니다.
- 새 파일 이름을 고를 때 같은 이름으로 남아 있는 백업을 덮어쓰지 않도록 다른 이름(` (2)`)을 씁니다.

평소처럼 파일이 잠겨 있지 않으면 달라지는 것이 없습니다. 백업 형식과 태그 형식은 그대로라 이전 버전의 백업으로도 되돌릴 수 있고, [음악 폴더 정리](https://github.com/microhan1/music-folder-organizer)와의 연동도 그대로입니다.

### 다운로드

`music-tag-filler.exe`를 받아 더블클릭합니다. fpcalc(Chromaprint, LGPL-2.1)와 AcoustID 키가 들어 있어 별도 설정 없이 소리로 찾기까지 됩니다. 서명되지 않은 exe라 SmartScreen 경고가 뜨면 "추가 정보 → 실행".

**Music Tag Filler v0.1.8** — safer undo backups; searching and screens are the same as v0.1.7. With "rename on save" on, a backup (`.tagbak.json`) held open by another program (antivirus, search indexer) could stay under the old name while the music file was renamed, so Undo said "no backup". The file and its backup now always move together or not at all; if the rename fails the tags are still saved and a warning says the file was not renamed (this used to be reported as a failed save). A save stops before writing anything when the existing backup cannot be read, and a new name never overwrites a leftover backup. Backup and tag formats are unchanged.
